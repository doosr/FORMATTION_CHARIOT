Électronique de Base — Ce qu'il faut savoir
Tension, courant, résistance, loi d'Ohm — les fondamentaux avant de câbler
🟢 Débutant
⚡ Loi d'Ohm — La règle d'or
U = R × I
U
Tension (V)
Volt
R
Résistance (Ω)
Ohm
I
Courant (A)
Ampère
🔍
Exemple concret : LED sur ESP32
GPIO ESP32 = 3.3V · Courant LED max = 20mA
→ R = U/I = (3.3 - 2.0) / 0.020 = 65 Ω
→ Utiliser résistance 68Ω ou 100Ω (standard)
⚠️
Diviseur de tension — Quand on l'utilise
Le capteur AJ-SR04M sort 5V sur ECHO. L'ESP32 accepte max 3.3V.
Formule : Vout = Vin × R2/(R1+R2)
→ R1=1kΩ, R2=2kΩ → Vout = 5 × 2/3 = 3.33V ✓
🔌
Pull-up / Pull-down résistances
OneWire (DS18B20) nécessite une résistance pull-up 4.7kΩ entre DATA et VCC pour forcer le signal à HIGH au repos. Sans elle, le signal flotte aléatoirement.
🧩 Composants courants dans ce projet
🔴
Résistance
Limite le courant. Bandes de couleur pour lire la valeur. Unité : Ohm (Ω). Dans ce projet : 4.7kΩ (pull-up OneWire), 1kΩ + 2kΩ (diviseur tension ultrason), 150Ω (base transistor).
🟡
Condensateur
Stocke et lisse l'énergie. Le SIM808 a besoin d'une capacité 1000µF 6.3V pour absorber les pics de courant lors des connexions GSM (jusqu'à 2A en impulsion).
🔵
Transistor NPN 2N2222
Interrupteur électronique contrôlé par un signal 3.3V. Le GPIO ESP32 (3.3V max 12mA) ne peut PAS alimenter directement un vibreur 5V/200mA. Le transistor amplifie le signal pour contrôler des charges plus puissantes.
⚡
Régulateur AMS1117-3.3V
Convertit 5V USB en 3.3V stable pour alimenter certains modules. Déjà intégré sur la plupart des cartes ESP32 DevKit.
🔲
Breadboard (plaque d'essai)
Permet de câbler sans souder, idéal pour les prototypes. Les rangées centrales sont connectées horizontalement, les rails ± sont connectés verticalement sur toute la longueur.

Capteurs & Câblage ESP32 Chariot
Chaque composant expliqué, son rôle, son protocole, et comment le brancher correctement
🔵 Intermédiaire
🔴 Avancé
⚡ Composants & Rôles détaillés
📡
SIM808 — GPS + Connectivité Internet
Fournit position GPS (lat/lon/altitude/vitesse via trame NMEA $GPRMC) ET connexion internet via SIM 4G. Communication UART à 9600 bps. Commandes AT pour gérer la connexion. Alimentation séparée 4V/2A OBLIGATOIRE — jamais par USB !
🌡️
DS18B20 — Température moteur OneWire
Capteur numérique : renvoie la temp en format 12-bit via bus OneWire (1 seul fil de données). Plage : -55°C à +125°C. Précision ±0.5°C. Résistance pull-up 4.7kΩ entre DATA et 3.3V OBLIGATOIRE. Adressable (plusieurs sur 1 GPIO).
📏
AJ-SR04M — Obstacle arrière Ultrason
Capteur ultrasonique waterproof (IP67). Portée 25cm–600cm. Envoie impulsion TRIG 10µs → mesure durée ECHO → distance = (durée × 340m/s) / 2. Sort 5V sur ECHO → diviseur de tension R1=1kΩ + R2=2kΩ nécessaire.
⛽
Capteur carburant — Jauge résistive analogique
Flotteur mécanique connecté à un potentiomètre. Résistance varie de ~10Ω (plein) à ~180Ω (vide). On mesure la tension via ADC ESP32 et on calcule le % avec une formule de mapping linéaire. GPIO34 ou 35 (Input Only).
🔧
Capteur pression huile — Analogique 0-5V
Sortie 0.5V–4.5V proportionnelle à 0–10 bar. Nécessite diviseur de tension (5V → 3.3V) avant de connecter à l'ADC ESP32. Formule : Pression (bar) = (Vout - 0.5) / (4.5 - 0.5) × 10
🚨
Buzzer actif + Transistor 2N2222
GPIO ESP32 (12mA max) insuffisant pour buzzer (50mA). Solution : transistor en commutateur. Base via R=150Ω, Collecteur → buzzer → 5V, Émetteur → GND. Signal 3.3V du GPIO contrôle 5V/50mA via le transistor.

📡 S1 · Module 4 · Jour 4
Protocoles de Communication
UART · I2C · OneWire · SPI — comment les composants parlent entre eux
🔵 Intermédiaire
🔴 UART — Universal Asynchronous Receiver/Transmitter
Protocole série point-à-point : 2 fils (TX et RX). L'émetteur et le récepteur doivent être configurés à la même vitesse (baud rate). Cross-connect : TX d'un côté → RX de l'autre.

Utilisé pour :
→ SIM808 GPS (9600 baud, UART2)
→ Moniteur série débogage (115200 baud)
→ Modules Bluetooth série
// UART2 pour SIM808 HardwareSerial sim808(2); void setup() { // Baud, RX pin, TX pin sim808.begin(9600, SERIAL_8N1, 16, 17); // Envoyer commandes AT sim808.println("AT"); sim808.println("AT+CGNSPWR=1"); }
🔵 I2C — Inter-Integrated Circuit (bus SDA/SCL)
Bus à 2 fils seulement : SDA (données) et SCL (horloge). Permet de connecter jusqu'à 127 périphériques sur le même bus ! Chaque composant a une adresse unique (7 bits).

Utilisé pour :
→ OLED SH1106 (adresse 0x3C)
→ MAX30102 BPM (adresse 0x57)
→ MLX90614 IR Temp (adresse 0x5A)
// I2C ESP32 : SDA=21 SCL=22 Wire.begin(21, 22); // Scanner I2C — trouver // l'adresse d'un composant for(int addr=1; addr<127; addr++){ Wire.beginTransmission(addr); if(Wire.endTransmission()==0) Serial.println(addr, HEX); }
🟡 OneWire — Bus 1 fil (DS18B20)
Protocole 1 seul fil de données ! Chaque capteur DS18B20 a une adresse ROM unique de 64 bits gravée en usine. On peut chaîner plusieurs capteurs sur un seul GPIO. Pull-up 4.7kΩ OBLIGATOIRE.

Bibliothèque PlatformIO :
OneWire + DallasTemperature
#include <OneWire.h> #include <DallasTemperature.h> OneWire oneWire(4); // GPIO 4 DallasTemperature sensors(&oneWire); sensors.requestTemperatures(); float temp = sensors .getTempCByIndex(0); // Résultat : 87.5 °C

FreeRTOS — Tâches Parallèles sur ESP32
Exécuter GPS, capteurs, MQTT et ultrason en même temps — la puissance du dual-core
🔴 Avancé — C++ / FreeRTOS
⚡ Architecture FreeRTOS — 5 Tâches en parallèle
L'ESP32 a 2 cœurs (Core 0 et Core 1). FreeRTOS permet d'exécuter plusieurs tâches indépendantes comme un vrai OS. Chaque tâche a sa propre pile mémoire et sa propre priorité.
Task_GPS — Core 0 · toutes les 5 secondes · Priorité 2
Lit trames NMEA $GPRMC du SIM808 via Serial2. Extrait lat/lon/speed/altitude. Calcule distance parcourue avec formule Haversine (trigonométrie sphérique). Met à jour variable globale protégée par mutex.
Task_Sensors — Core 0 · toutes les 500ms · Priorité 3
Lit DS18B20 (temp OneWire), ADC carburant GPIO34, ADC pression GPIO35. Applique filtre moyenne glissante sur 5 mesures pour éliminer les faux pics. Détecte anomalies (temp > 95°C, pression < 1 bar).
Task_Ultrason — Core 0 · toutes les 300ms · Priorité 4
Envoie pulse TRIG 10µs, mesure durée ECHO avec pulseIn(), calcule distance = (durée × 0.034) / 2 cm. CAUTION si <80cm, DANGER si <40cm. Active buzzer PWM + envoie struct ESP-NOW bracelet.
Task_Telemetry — Core 1 · toutes les 500ms · Priorité 3
Assemble toutes les données en JSON (ArduinoJson), publie sur MQTT topic intellimetry/{id}/telemetry. Vérifie connexion WiFi/MQTT et reconnecte si nécessaire. Envoie struct ESP-NOW en broadcast.
Task_WiFiManager — Core 1 · sur événement · Priorité 1
Surveille la connexion WiFi. Si WiFi perdu → tente reconnexion 3 fois → ouvre portail captif (hotspot) pour reconfiguration. Gère aussi le heartbeat MQTT status toutes les 10 secondes.
📦 Code FreeRTOS — Créer une tâche
// Variables partagées (protégées par mutex) struct TelemetryData { float temp, fuel, oil, lat, lon, speed; int proximity, gear; bool engineOn; } telemetry; SemaphoreHandle_t mutex = xSemaphoreCreateMutex(); // Définir une tâche FreeRTOS void Task_Sensors(void* param) { for(;;) { // boucle infinie xSemaphoreTake(mutex, portMAX_DELAY); telemetry.temp = sensors.getTempCByIndex(0); telemetry.fuel = map(analogRead(34), 0,4095, 0,100); xSemaphoreGive(mutex); vTaskDelay(500 / portTICK_PERIOD_MS); } } void setup() { // Lancer les tâches sur les cores xTaskCreatePinnedToCore( Task_Sensors, "Sensors", 4096, NULL, 3, NULL, 0); xTaskCreatePinnedToCore( Task_Telemetry, "Telemetry", 8192, NULL, 3, NULL, 1); }
⚠️ Points critiques FreeRTOS
🔴
Race Condition : Sans mutex, deux tâches peuvent lire/écrire la même variable simultanément → données corrompues. Toujours protéger les variables partagées avec xSemaphore.
🟡
Stack Size : Chaque tâche nécessite sa propre pile. Trop petite → crash. Trop grande → gaspillage RAM. Typiquement 4096 bytes pour tâches simples, 8192 pour MQTT/JSON.
🔵
delay() interdit : Utiliser vTaskDelay() au lieu de delay() dans les tâches FreeRTOS pour ne pas bloquer le scheduler.

💡 Pourquoi ESP-NOW et pas MQTT ?
ESP-NOW est peer-to-peer, direct, sans passer par internet. Latence <5ms vs ~50-200ms MQTT. Parfait pour les alertes de sécurité temps-critique où chaque milliseconde compte. Range 220m en ligne directe.
📡 S2 · Module 8 · Jour 8
Protocole MQTT — Comment ça marche ?
Topics, payload JSON, QoS, Broker HiveMQ — Le standard IoT mondial
🟢 Débutant — Explication simple !
💡 MQTT c'est quoi ? (analogie radio)
📻
C'est comme une radio : L'ESP32 (émetteur) publie sur une "fréquence" (topic). Le serveur et le dashboard (récepteurs) sont abonnés à cette fréquence et reçoivent le message immédiatement. Le broker = la tour de diffusion.
📨 Les 4 Topics du système IntelliMettry
intellimetry/{deviceId}/telemetryPUBLISH
ESP32 envoie toutes les données (temp, fuel, GPS, ultrason) toutes les 500ms · QoS 0
intellimetry/{deviceId}/alertSUBSCRIBE
Backend envoie alertes vers ESP32 (géofence, surchauffe, immobilisation)
intellimetry/{deviceId}/commandSUBSCRIBE
Dashboard envoie commandes : changer mode bracelet, déclencher alarme
intellimetry/{deviceId}/statusPUBLISH
Heartbeat toutes les 10s : online/offline, WiFi RSSI, uptime
🔑 Niveaux de QoS — Qualité de Service
0
At most once
Envoi sans confirmation. Plus rapide. OK pour télémétrie 500ms.

🔑 JWT — Comment ça marche ?
JSON Web Token = 3 parties encodées en Base64 séparées par des points :
Header : algorithme (HS256) + type (JWT)
Payload : userId, email, role, exp (expiration)
Signature : HMAC-SHA256 (header.payload + secret)
// Générer un token JWT à la connexion const jwt = require('jsonwebtoken'); const bcrypt = require('bcrypt'); // Login route router.post('/login', async (req, res) => { const user = await User.findOne({email}); const valid = await bcrypt.compare( password, user.passwordHash ); if(!valid) return res.status(401).json({error:'Unauthorized'}); const token = jwt.sign( { userId: user._id, role: user.role }, process.env.JWT_SECRET, { expiresIn: '7d' } ); res.json({ token, role: user.role }); });
🛡️ Middleware de protection
// middleware/authMiddleware.js module.exports = (roles=[]) => (async (req, res, next) => { const auth = req.headers.authorization; if(!auth?.startsWith('Bearer ')) return res.status(401).json({error:'No token'}); const token = auth.split(' ')[1]; try { const decoded = jwt.verify( token, process.env.JWT_SECRET ); req.user = decoded; // Vérifier le rôle si spécifié if(roles.length && !roles.includes(decoded.role)) return res.status(403).json( {error:'Forbidden'} ); next(); } catch(e) { res.status(401).json({error:'Invalid'}); } }); // Utilisation dans une route router.delete('/:id', authMiddleware(['superadmin']), deleteController );

🔒 Bonnes pratiques sécurité
✅
Mots de passe : Toujours hasher avec bcrypt (coût 12). Jamais stocker en clair. Jamais logguer.
✅
JWT Secret : Minimum 256 bits aléatoires. Variable d'environnement. Jamais en dur dans le code.
✅
Rate Limiting : Express-rate-limit : max 100 req/15min sur /api/auth pour éviter les attaques bruteforce.
✅
CORS : Restreindre les origines autorisées avec le package cors. Seul le frontend domain peut appeler l'API.
✅
Helmet.js : Middleware de sécurité HTTP headers (CSP, HSTS, X-Frame-Options) en 1 ligne.
✅
MQTT TLS : Utiliser port 8883 avec certificat TLS pour chiffrer les données MQTT en transit.
✅
Validation entrées : express-validator sur toutes les routes. Ne jamais faire confiance aux données client.

🌍 Géofencing — Formule Haversine
d = 2R × arcsin(√(sin²(Δlat/2) + cos(lat1)×cos(lat2)×sin²(Δlon/2)))
function haversine(lat1, lon1, lat2, lon2) { const R = 6371000; // rayon Terre en mètres const dLat = (lat2-lat1) * Math.PI/180; const dLon = (lon2-lon1) * Math.PI/180; const a = Math.sin(dLat/2)**2 + Math.cos(lat1*Math.PI/180) * Math.cos(lat2*Math.PI/180) * Math.sin(dLon/2)**2; return R * 2 * Math.atan2(Math.sqrt(a), Math.sqrt(1-a)); } async function checkGeofence(deviceId, lat, lon) { const machine = await Machine.findOne({deviceId}); const dist = haversine(lat, lon, machine.geofence.lat, machine.geofence.lon); if(dist > machine.geofence.radius) { triggerAlert('GEOFENCE_BREACH', deviceId, {distance: dist}); } }
